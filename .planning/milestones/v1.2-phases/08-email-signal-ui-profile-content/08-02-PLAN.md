    The default view is `signalFilter: 'untriaged'` — shows contacts with NO signal assigned (`connections.latest_signal IS NULL`). This keeps the daily triage focused: "work through these untriaged contacts, then you're done."

    **Part B: Modify the PostgREST query in renderQueue():**

    The existing status filter `.eq('status', queueFilters.statusFilter)` needs to evolve:

    - When `signalFilter === 'untriaged'`: Fetch all `pending_review` items (server-side). After fetch, client-side filter to only show items where `conn.latest_signal` is null AND `conn.user_priority !== 'never'` (exclude ARCHIVE).
    - When `signalFilter` is a specific signal name (e.g., 'WARM_LEAD'): Fetch all items (no status filter server-side). Client-side filter to items where `conn.latest_signal === signalFilter`.
    - When `signalFilter === 'all'`: Fetch all items (no status filter). Client-side filter to exclude `conn.user_priority === 'never'` (hide ARCHIVE from "all" view).

    IMPORTANT: Do NOT attempt to filter on `connections.latest_signal` via PostgREST server-side — PostgREST does not support filtering on embedded resource fields. Use client-side filter after fetch (same pattern as industryFilter). See Pitfall 3 in research.
