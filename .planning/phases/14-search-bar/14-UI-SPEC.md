## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gap from input edge (`left: 4px` pseudo-padding), label gap |
| sm | 8px | Icon left offset inside search input, compact element spacing |
| md | 16px | Filter bar padding, card padding, default element spacing |
| lg | 24px | Section separation |
| xl | 32px | Layout gaps |
| 2xl | 48px | Empty state top/bottom padding |
| 3xl | 64px | Page-level spacing (not used in this phase) |

Exceptions:
- Search input left padding: 28px (sm + icon-width: 8 + 16 + 4 clearance) — clears the 16px icon. Use `padding-left: 28px` on `.search-input`.
- Touch targets for clear button (X): minimum 32px hit area (fits within sm/md bounds).

Source: default scale with search-icon-clearance exception from RESEARCH.md `CSS for Search Input with Icon`.

## Interaction Contract

### Search input behavior

| Event | Response |
|-------|----------|
| User types (keystroke) | Start 300ms debounce timer; reset existing timer |
| 300ms passes after last keystroke | Fire search query if `value.length >= 2` |
| Input cleared (value = '') | Reset `searchQuery = ''`, reset offset, re-render immediately (no debounce) |
| Input has 1 character | Clear debounce timer; do not fire query; do not clear existing results |
| `type="search"` native clear (X) | Fires `oninput` → treated as empty string → immediate re-render |

Minimum query length: 2 characters (matches existing role filter pattern; single characters yield noise and excess queries).

Debounce: 300ms (locked in CONTEXT.md, matches Phase 13 role filter pattern).

Source: CONTEXT.md `Debounce` decision + RESEARCH.md Pattern 7 + existing `onContactRoleInput()` pattern.

### Filter interaction

| State | Behavior |
|-------|----------|
| Search active + Industry filter active | AND logic — contacts must match both |
| Search active + Location filter active | AND logic — contacts must match both |
| Clear search bar only | Industry/Location filters preserved |
| Clear Industry/Location filter | Search text preserved |
| "Clear filters" / "Clear all" button | Resets searchQuery, industryFilter, cityFilter simultaneously |

"Clear all" button label: `Clear filters` (existing label in `clearContactFilters()`, no change needed).

Source: CONTEXT.md `Independent clearing` + `AND logic with existing filters` decisions.

### Loading state

No full-page spinner for search queries. The existing spinner (`<div class="loading"><div class="spinner">`) fires only on initial page load (`offset === 0` with no prior data).

For search-in-flight: results list stays visible at normal opacity. Debounce absorbs perceived latency. No additional loading indicator introduced in this phase.

Source: RESEARCH.md Open Question 3 resolution (Claude's discretion: no full-page spinner for search).

### Sort order

`reconnect_score` descending always — no change when search is active.

Source: CONTEXT.md `Score sort always` decision.

### Result highlighting

No term highlighting. Same card rendering as browse mode — no bold, no mark tags on matched terms.

Source: CONTEXT.md `No term highlighting` decision.

## States and Transitions

| State | Trigger | UI |
|-------|---------|-----|
| Browse (default) | Page load, no search | Filter bar (search input empty) + count banner "Showing X of Y" + paginated list |
| Searching | User types 2+ chars, debounce fires | Same layout; count banner switches to "X contacts match..." |
| No results (search) | searchQuery active, count = 0 | Empty state with magnifying glass emoji + no-results copy |
| No results (browse) | No search, no contacts | Empty state with group emoji + import prompt |
| Loading (initial) | Page first render | Full spinner replaces list |
| Error | API call fails | Warning emoji + error copy |
| Load more | User taps Load more | Button becomes `Loading...` + disabled; new rows appended |
