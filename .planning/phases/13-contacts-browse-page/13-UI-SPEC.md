## Interaction Contract

### Contact Row
- Tap target: entire `.contact-row` element (full card)
- Tap action: `navigate('#/contact/{id}')` — navigates to existing contact profile
- Active/press state: `background: #f8f9fa` on `:active` (subtle, matches `.btn:active` scale pattern)
- No hover state needed (mobile-first)

### Role Filter Input
- Input type: `text`, tied to `<datalist id="role-suggestions">`
- Debounce: 300ms before firing suggestion fetch
- Minimum characters: 2 characters before fetching suggestions
- Suggestion fetch: `db.from('connections').select('enriched_headline').ilike(...).limit(10)`
- Filter fires: on user selection from datalist OR on input clear (empty string)
- Empty clear: clears `contactFilters.roleQuery`, resets `offset = 0`, re-renders

### Industry Dropdown
- Element: `<select>` with "All" as first option (value `""`)
- Population: fetched on page load via `fetchFilterOptions()` — parallel with city fetch
- Change: sets `contactFilters.industryFilter`, resets `offset = 0`, re-renders

### Location Dropdown
- Element: `<select>` with "All" as first option (value `""`)
- Population: fetched on page load via `fetchFilterOptions()` — parallel with industry fetch
- Change: sets `contactFilters.cityFilter`, resets `offset = 0`, re-renders

### Clear Filters Button
- Appearance: shown only when ANY filter is active (`roleQuery || industryFilter || cityFilter`)
- Style: `.btn btn-sm btn-outline` — text "Clear filters"
- Placement: below the Industry/City dropdowns row, right-aligned (flex `align-self: flex-end`)
- Action: clears all three filters, resets offset to 0, re-renders

### Load More Button
- Style: `.btn btn-outline` — text "Load more contacts"
- Placement: `.load-more-container` centered div below the contact list
- Visibility: shown only when `_contactRows.length < contactFilters.totalCount`
- Hidden when: all matching contacts are already shown, or zero results
- Loading state: button disabled + text "Loading..." during fetch

### Filter Value Fetching Strategy
- Fetch distinct industries and cities in parallel on page load (two separate queries via `Promise.all`)
- Cache in module-level `_filterOptions` object — do NOT re-fetch on filter changes
- Fetch happens once per page mount; reset on page navigation away

### Count Banner
- Text: "Showing {N} of {Y} contacts"
- Position: below the filter bar, above the first contact row
- Updates on every render (initial load + load more + filter change)
- Hidden when total count is 0

### Loading State (initial)
- Show `.loading` spinner while first data fetch is in flight
- Replace container content with spinner; do not show skeleton rows
- Consistent with existing `queue.js` loading pattern

### Count Query Approach
- Use `select(BROWSE_SELECT, { count: 'exact' })` — single request returns both rows and total count
- No separate COUNT query
- `count: 'exact'` on initial load and every filter change
- Load More requests omit count (pass `{ count: 'planned' }` or omit — count already known)

## Field Selection Contract

`BROWSE_SELECT` constant must contain exactly these columns — never `select('*')`:

```javascript
const BROWSE_SELECT = [
  'id',
  'name',
  'current_role',
  'current_company',
  'enriched_industry',
  'enriched_city',
  'enriched_headline',
  'reconnect_score',
  'latest_signal',
  'user_priority'
].join(',');
```

`raw_enrichment` is explicitly excluded. Adding it to BROWSE_SELECT is a blocking error (BROWSE-05).
