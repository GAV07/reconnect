<objective>
Add GET/POST split to the action Edge Function (preventing Gmail scanner token consumption) and add query-parameter deep link bridge to the PWA.

Purpose: Gmail security scanners issue GET requests to all email links before delivery, consuming one-time action tokens. Users tap "Yes" and see "Already Used." Additionally, "View Profile" deep links from email need to use query parameters (not hash fragments) because Gmail's redirect chain strips fragments per RFC 3986. The PWA needs to read query parameters on startup and convert them to hash routes.

Output: Updated action/index.ts with GET -> confirmation form, POST -> execute action. Updated app.js with checkDeepLinkQueryParams() startup bridge. Edge Function deployed to Supabase.
</objective>

  <action>
    Add a `checkDeepLinkQueryParams()` function to `pwa/js/app.js` that runs at startup BEFORE `render()`:

    ```javascript
    function checkDeepLinkQueryParams() {
      const params = new URLSearchParams(window.location.search);
      const view = params.get('view');
      const id = params.get('id');
      if (view === 'contact' && id) {
        // Clean query params from URL bar, then set hash route
        history.replaceState(null, '', window.location.pathname);
        window.location.hash = `/contact/${id}`;
        return true; // hashchange event will trigger render()
      }
      return false;
    }
    ```

    Modify the `DOMContentLoaded` handler (currently at line 106-110):
    ```javascript
    document.addEventListener('DOMContentLoaded', () => {
      initSupabase();
      setupOfflineDetection();
      if (!checkDeepLinkQueryParams()) {
        render(); // only call render() if we didn't trigger a hashchange
      }
    });
    ```

    The function must:
    1. Read `window.location.search` (NOT `window.location.hash`)
    2. Check for `view=contact` and `id` parameters
    3. If found: call `history.replaceState` to clean the URL, then set `window.location.hash` to the correct route
    4. Return true if a deep link was handled (so render() is not called twice -- the hashchange listener will call render())
    5. Return false otherwise (so render() proceeds normally)

    Place the function definition BEFORE the DOMContentLoaded listener, after the `setupOfflineDetection` function definition.
